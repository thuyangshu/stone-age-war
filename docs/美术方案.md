## 二、风格决策（统一语言，避免混搭显业余）

**定调：扁平矢量卡通为主体，武器加材质细节档。**

| 元素 | 风格 | 理由 |
|---|---|---|
| 角色 | 图 1 语言：扁平、无描边、圆润几何、高饱和暖色 | 游戏内角色仅约 80-120px 高，半写实细节会糊成一团；扁平风在小尺寸下可读性最好，且动画帧一致性容易保持 |
| 武器 | 图 1 造型语言 + 图 2 材质配色（灰石/红棕木/深皮革）：扁平形状、但增加 1-2 档材质明暗 | 武器在背包/选择栏里会放大显示，需要辨识度；但保持扁平形状语言才不破坏统一 |
| 地形/背景 | 程序化绘制：色块分层+柔渐变，不做照片级噪点 | 需动态生成（每局随机）、分层视差、随相机缩放 |
| UI | 程序化：骨形血条、石钮、木牌面板，暖棕+米白，圆角无描边 | 与角色同源 |

## 三、版权规避清单

## 四点五、实测记录（2026-09-26 首次跑通）

**环境**：Draw Things API（7860）+ FLUX，M3 Max。调用脚本 `tools/gen-image.mjs`。

### 速度实测
| 模型 | 步数 | 尺寸 | 耗时 |
|---|---|---|---|
| `flux_1_schnell_q8p.ckpt` | 6 | 768×1024 | 38.3s |
| `flux_1_schnell_q8p.ckpt` | 6 | 640×896 | 22-29s |
| `flux_1_dev_q8p.ckpt` | 20 | 640×896 | 87.7s |

### 提示词迭代（3 轮才命中风格）
| 轮次 | 提示词要点 | 结果 |
|---|---|---|
| 1 | `flat vector cartoon, prehistoric warrior...` | ❌ 出成"可爱卡通"：全身描边、渐变、3.5 头身像小孩、精细大眼 |
| 2 | 改 `flat vector illustration` + 强调 `solid flat color shapes only, no outlines, no gradients, no shading` + 负面词 | ✅ 命中：无描边、纯色块、6-7 头身成人、锯齿下摆 |
| 3 | 加 `standing side profile facing right` + `no ground shadow` | ✅ 侧向达成；地面投影仍在（负面词压不掉） |

**结论：FLUX 默认画风是"带描边+渐变的可爱卡通"，必须靠精确的风格锚词强压**。关键锚词组合（已验证有效）：
```
flat vector illustration, solid flat color shapes only, minimalist geometric design,
no outlines, no gradients, no shading, editorial vector art style, isolated on pure white background
```
配套负面词：
```
outline, gradient, shading, drop shadow, ground shadow, 3d render, chibi, child,
big head, detailed eyes, texture, watermark, text, multiple people
```

### 两个模型的分工结论（2026-09-26 作者看过样张后定档）
| | schnell（6 步，~25s） | **dev（20 步，~88s）← 主力** |
|---|---|---|
| 风格倾向 | 卡通概括，更接近参考图 1 家族 | **半写实扁平插画，更精致** |
| 指令遵循 | 侧向、纯色块等字面指令跟得准 | 画面更美，偶有自由发挥 |
| 定位 | 只用于快速验证提示词是否可用 | **全部正式素材出图** |

**作者裁决：dev 样张质量优于 schnell，全部素材以 dev 出图**。schnell 退回"提示词试错"单一用途（省时间），任何进入 `assets/` 的成品一律 dev。工具链默认值已按此设置（`tools/make-asset.sh` 默认 `--model flux_1_dev_q8p.ckpt --steps 20`）。

### 地面投影问题（待处理）
提示词和负面词都压不掉 FLUX 默认加的脚下椭圆阴影。**解法不靠提示词，靠后期**：生成时用白底，出图后程序化抠掉白底——投影一并去除。这是游戏精灵图的标准流程，本来就是必需步骤。

## 五、生产流程

```
FLUX 生成（tools/gen-image.mjs）
  → 去背景/裁剪（ImageMagick 或纯 JS PNG 处理）
  → 存入 assets/ 并人工/模型审图（用 deepseek-flash 读图提意见）
  → 不合格则改提示词重出（固定 seed 微调）
  → 定稿素材接入游戏 js/textures.js 加载
```

**审图闭环**：生图模型不会自我审查，但 deepseek-flash 能读图 → 生成后立即让它对照"无描边/暖色调/造型合规/无水印/无多余肢体"逐项检查，自动迭代。
