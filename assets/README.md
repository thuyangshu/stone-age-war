# assets/ —— 未接入游戏的实验产物

**本目录的 PNG 目前一个都没有被游戏使用。** 游戏的全部美术由 `js/textures.js`
用 Canvas 2D 程序生成，运行时不加载任何图片文件——所以删掉整个 `assets/`
游戏照跑，`smoke.sh` 照绿。

## 这里放的是什么

用本机 Draw Things 跑 FLUX 生成的样张，目的是评估"字符与武器改用扩散模型出图"
这条路值不值得走：

| 文件 | 说明 |
|---|---|
| `test-warrior*.png` | 早期风格试验（三版） |
| `test-warrior3-dev.png` / `-schnell.png` | 同一提示词下 **dev 与 schnell 两个模型的对比样张** |
| `*-cut.png` | 用 `tools/cutout.py` 去背景的结果 |
| `hero-a-idle.png`、`weapon-axe.png` | 按 `docs/美术方案.md` 调色板生成的两件候选产物 |

## 结论（作者已拍板）

**dev 比 schnell 好**，若要继续走这条路，生产模型用 dev。

## 待办（P2 候选，非 P1 交付所需）

若决定接入，需要补的量：

- 武器图标 7 件（现只有石斧一件）
- 主角 B 的立绘与姿势帧（现只有主角 A 的待机）
- 姿势帧：待机 / 蓄力 / 投掷 / 受击 / 死亡

单张约 88 秒。接入时要解决的是**风格统一**——`docs/美术方案.md` 的版权规避清单
要求角色造型、服饰、面部特征全部原创，扩散模型出图不容易保证多张之间的一致性，
而这正是程序化绘制天生擅长的地方。走这条路的收益与风险都记在这里，供 P2 决策。
